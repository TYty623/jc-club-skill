# 架构提炼：社区平台的职责分层

## 请求路径

```text
客户端
  │
Gateway：路由、请求 ID、粗粒度防护、统一错误
  │
认证边界：验证凭据，产生可信身份声明
  │
业务服务：题库 / 练习 / 圈子 / 面试 / 对象存储 / 微信接入
  │
应用层：用例编排、事务、事件
  │
领域层：规则、聚合、领域接口
  │
基础设施：DB、Redis、RPC、MQ、Nacos、OSS
```

## 不变原则

| 层或边界 | 应负责的事情 | 不应负责的事情 |
| --- | --- | --- |
| Gateway | 路由、限流、链路标识、统一协议错误 | 题目规则、用户资料写入、跨表事务 |
| Auth | 凭据验证、身份/角色声明 | 业务资源的所有细节判断 |
| Application | 用例、事务、权限到领域规则的映射 | 直接拼接基础设施细节 |
| Domain | 可测试的业务规则和领域接口 | HTTP、SQL、Redis 客户端代码 |
| Infrastructure | 外部系统适配和可靠性机制 | 决定核心业务策略 |

## 可观测性基线

- 每个入口生成或继承 request ID，并在 RPC、消息与日志中传递。
- 将认证失败、权限拒绝、业务校验失败和依赖超时区分记录。
- 对缓存未命中、慢查询、消息重试和外部服务失败建立可查询指标。
